ПОСТИ: ПОШУК, СТВОРЕННЯ, РЕДАГУВАННЯ

На цьому занятті вам потрібно реалізувати проєкт з Next.js 15, використовуючи App Router, React Query, та сучасний підхід до організації маршрутизації, модалок і SSR.

В основі — готовий застосунок із попереднього заняття, який було перенесено з React у Next.js. Ваше завдання — правильно організувати структуру сторінок та додати логіку до файлів у директорії app, використовуючи серверні та клієнтські компоненти залежно від задачі.

Загальна інформація

У проєкті вже є усі необхідні компоненти та файли сторінок.
Усі запити реалізуються через axios у файлі lib/api.ts.
Типи оголошені у types/post.ts.
Підключена бібліотека React Query (TanStackProvider вже винесений).

Backend

Використовуйте бекенд JSONPlaceholder API — це публічний REST API, який імітує роботу реального сервера. У рамках практики ми будемо взаємодіяти з ресурсами пости та користувачі, використовуючи такі ендпоінти:

Робота з постами

GET /posts - для отримання списку постів. Приймає параметри:

userId — фільтрація постів за ID користувача (необов’язково).
q — пошук за текстом у постах (необов’язково).
\_page, \_limit — пагінація (обмеження кількості постів на сторінці та вибір сторінки).
Повертає: масив постів та загальну кількість у заголовках відповіді.

POST /posts — для створення нового поста. Тіло запиту:

title — заголовок поста
body — текст поста
Повертає: створений пост.

PATCH /posts/:id — для редагування існуючого поста. Тіло запиту:

title — новий заголовок
body — новий текст
Повертає: оновлений пост.

DELETE /posts/:id — для видалення поста. Параметри URL.

Повертає: видалений пост.

GET /posts/:id — для отримання конкретного поста.

Повертає: об’єкт поста.

Робота з користувачами

GET /users — для отримання списку всіх користувачів.

Повертає: масив користувачів.

GET /users/:id — для отримання конкретного користувача.

Повертає: об’єкт користувача.

Фінальна структура app/

app/
├── @modal/
│ └── (.)posts/
│ └── [id]/
│ └── page.tsx // Сторінка перегляду поста в модальному вікні
│
├── posts/
│ ├── [id]/  
│ │ └── page.tsx // Сторінка перегляду одного поста
│ │

│ │ └── page.tsx // Сторінка перегляду постів за фільтром автор

│

СТОРІНКА posts: реалізація сторінки зі списком постів, пошуком, пагінацією, створенням та редагуванням

Реалізуйте сторінку /posts/filter/[userId], яка виводить список постів з можливістю:

перегляду;
пошуку за назвою та вмістом;
фільтрацієї за юзером (автором) поста
пагінації;
створення нового поста;
редагування наявного поста.

Опишіть у файлі lib\api.ts функцію fetchUsers. Вона має робити запит на бекенд (https://jsonplaceholder.typicode.com/users) і повертати список усіх юзерів.

Для реалізації маршруту використовується динамічна сторінка app/posts/filter/[...slug]/page.tsx, де перший сегмент slug[0] відповідає userId, за яким фільтруються пости. Наприклад, шлях /posts/All відображає всі пости, а /posts/3 — лише пости користувача з id === 3.

У цьому маршруті реалізуйте SSR: безпосередньо у page.tsx викликається функція fetchPosts, яка отримує початкові дані з бекенда, а потім передає їх до клієнтського компонента PostsClient.

Також у файлі generateMetadata потрібно динамічно створити SEO-метадані на основі userId, наприклад, "Posts - All Users" або "Posts - User 3".

У компоненті PostsClient реалізовано всю логіку взаємодії з користувачем. Ви працюєте зі станами пошуку, поточної сторінки, відкриття модального вікна та вибору між створенням або редагуванням поста. Пошук реалізуйте з використанням debounce на 300 мс.

Для кожного запиту використовується React Query з ключем ['posts', searchQuery, currentPage, userId] та опцією keepPreviousData для плавної пагінації. Початкові дані для useQuery передаються через initialData, отриману із сервера.

У розмітці сторінки мають бути:

поле для пошуку;
компонент пагінації (тільки якщо сторінок більше однієї);
кнопка створення поста;
список постів, який формується з даних бекенда;
модальне вікно, яке відкривається або для створення, або для редагування поста.

Після створення або редагування поста потрібно оновити кеш списку постів за допомогою queryClient.invalidateQueries(["posts"]). У разі успішної дії виводиться повідомлення через alert(), після чого модальне вікно автоматично закривається, а форма очищується.

Структура

Файли сторінок знаходяться в директорії app/posts/filter/[...slug]/, де:

page.tsx — серверна сторінка, яка передає дані в PostsClient;
PostsClient.tsx — клієнтський компонент, який містить усю логіку;
layout.tsx — спільне оформлення для фільтраційної сторінки.
Інші компоненти, такі як PostList, SearchBox, Pagination, Modal, CreatePostForm, EditPostForm, вже готові і розташовані у відповідних папках.

API

Для отримання постів використовуйте функцію fetchPosts з модуля lib/api.ts. Вона приймає обʼєкт параметрів:

{
searchText: string;
page: number;
userId?: string;
}

У результаті

Після виконання завдання, ваш застосунок повинен мати сторінку /posts/filter/[userId], яка підтримує:

динамічний SSR на основі userId;
клієнтське керування станом і рендеринг;
інтуїтивний UX для пошуку, навігації, створення та редагування постів;
повну інтеграцію з React Query та App Router.

СТОРІНКА posts/[id]: реалізація перегляду окремого поста з SSR, React Query та SEO

У цьому завданні потрібно реалізувати сторінку перегляду одного поста за маршрутом /posts/[id]. Користувач має змогу переглянути заголовок, вміст поста та ім’я автора. Також реалізується кнопка повернення назад.

Для реалізації використовується App Router з серверним компонентом page.tsx, в якому необхідно:

Отримати id поста з параметрів;
Викликати функцію fetchPostById;
За допомогою React Query створити QueryClient і передзавантажити дані (prefetch);
Передати кешовані дані через компонент HydrationBoundary у клієнтську частину PostDetailsClient.

У файлі потрібно створити метаінформацію для SEO на основі даних поста: title дорівнює заголовку поста, а description — це перші 30 символів його вмісту (body).

У клієнтському компоненті PostDetailsClient.tsx потрібно:

Отримати id з useParams(), розпарсити його в число;
Використати useQuery з ключем ['post', id] та викликом fetchPostById;
Додатково після отримання поста зробити запит fetchUserById, щоб отримати ім’я автора;
Вивести завантаження (loading) або помилку (error), якщо потрібно;
Відобразити заголовок, вміст поста та ім’я автора;
Додати кнопку «← Back» з поведінкою router.back().

Структура

Файли сторінки знаходяться в директорії app/posts/[id]/, де:

page.tsx — серверний компонент, який передає дані через HydrationBoundary;
PostDetails.client.tsx — клієнтський компонент із викликами useQuery, запитом користувача та логікою рендерингу;

API

Отримання поста та автора

fetchPostById(id: number)

fetchUserById(userId: number)

У результаті

Після виконання завдання, ваша сторінка /posts/[id] повинна:

динамічно отримувати пост із сервера на основі id;
передзавантажувати дані за допомогою React Query ще на сервері;
використовувати HydrationBoundary для передачі стану в клієнт;
виводити повну інформацію про пост, включно з ім’ям автора;
мати динамічні метадані для SEO;
працювати без помилок при оновленні сторінки або прямому переході за посиланням.

Модальне вікно перегляду поста: реалізація перехоплення маршруту

Реалізуйте перегляд окремого поста у вигляді модального вікна за допомогою перехоплення маршруту.

Маршрут

При натисканні на пост зі списку /posts/filter/[userId], користувач переходить за адресою /posts/[id]. Щоб замість повної навігації до нової сторінки показати модальне вікно поверх поточної, необхідно створити перехоплюючий маршрут:

Завдання

1. У файлі app/(.)posts/[id]/page.tsx реалізуйте SSR:

Створіть новий QueryClient;
Перед рендером викличте queryClient.prefetchQuery, щоб завчасно завантажити пост за id;
Обгорніть компонент у HydrationBoundary з dehydrate(queryClient). 2. У клієнтському компоненті PostPreviewClient:

Отримайте id поста з useParams;
Отримайте дані поста через useQuery;
Додатково зробіть запит на автора поста через fetchUserById;
Відобразіть дані всередині компонента Modal;
Кнопка ← Back має викликати router.back() — це закриває модалку й повертає користувача до попередньої сторінки (/posts/filter/[userId]). 3. Рендеріть модальне вікно (<Modal />) лише тоді, коли пост завантажено.

4. Забезпечте виведення:

заголовка поста (post.title);
тіла поста (post.body);
імені автора (user.name). 5. Якщо дані ще не завантажено, виводьте повідомлення Loading, please wait.... У випадку помилки — Something went wrong.

Результат

Після реалізації:

Перехід /posts/[id] на сторінці /posts/filter/[userId] не замінює сторінку, а відкриває модальне вікно;
При закритті (натискання "Back") користувач повертається до /posts/filter/[userId];
Дані про пост і автора завантажуються з сервера через React Query;
Все працює згідно з поведінкою перехоплених маршрутів у Next.js App Router.
